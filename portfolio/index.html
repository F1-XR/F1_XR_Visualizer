My Little Grand Prix

The race. In your space.

외부 서비스가 준비한 과거 F1 데이터셋을 하나의 시간축에서 다중 차량 리플레이로 재구성하고, 선택한 이벤트를 실제 방의 Hero 지점에 MR 디오라마로 다시 배치한 Unity XR 프로젝트입니다.

01 Project thesis

Keep the race true. Move the presentation.

레이스의 시간과 차량 상태는 그대로 두고, 방 안에서 보이는 크기·방향·초점만 별도의 프레젠테이션 계층으로 다뤘습니다.

일반적인 화면 속 리플레이를 그대로 공간에 띄우는 대신, AR plane에서 서로 다른 두 벽을 Entry와 Exit로 고르고 사용자의 시선에 가까운 Hero 지점을 정의합니다. 확정된 방 프레임은 고정하고, 이벤트 로컬 트랙을 Hero 중심의 방 크기 디오라마로 강체 변환합니다.

Entry와 Exit는 배치 맥락과 방향을 정하지만, 현재 기본 차량 경로가 두 벽을 반드시 통과하는 것은 아닙니다. 이 차이를 숨기지 않고 현재 구현과 다음 개선 과제로 분리했습니다.

02 Runtime pipeline

From dataset to room-scale replay.

  1. Dataset request

    Unity 클라이언트가 companion REST 서비스의 catalog, dataset, manifest, chunk 계약을 사용합니다.

  2. Ready-range loading

    manifest 준비 상태를 polling하고 현재 재생 시각과 이벤트 구간에 필요한 ready chunk만 메모리로 가져옵니다.

  3. Source / playback split

    서버 위치 샘플을 시간순 정렬·동일 시각 중복 제거한 normalized source copy로 유지하고, 분리된 playback copy에 방향 글리치 제거와 움직임 안정화를 추가 적용합니다.

  4. Shared race clock

    로드된 차량을 하나의 source-time으로 샘플링해 pause, speed, seek를 일관되게 처리하고 red-flag downtime compression을 선택적으로 지원합니다.

  5. Room layout

    containing floor boundary가 확인된 자동 구성에서는 후보를 해당 경계로 제한합니다. 자동 구성이 성립하지 않으면 서로 다른 Entry/Exit 벽을 수동 선택하고 Hero pose와 확정 프레임을 구성합니다.

  6. Event diorama

    일반 이벤트의 첫 두 차량과 source-track shape를 event-local stage에 묶고 Hero를 중심으로 scale·yaw·position을 적용합니다.

데이터 출처 경계 — 이 Unity 저장소에는 OpenF1 fetcher가 없고 companion REST dataset만 소비합니다. 따라서 “OpenF1 직접 연동”이나 “실시간 F1 데이터”는 이 사례의 검증된 주장이 아닙니다.

05 Architecture

Two flows. One reversible stage.

06 Engineering challenges

Three constraints shaped the system.

Problem 01

Chunked data, coherent clock

데이터가 구간별로 늦게 준비되어도 차량마다 다른 시간을 보이면 안 됩니다. manifest와 ready range를 분리하고 모든 차량을 하나의 source-time에 샘플링했습니다. 대가로, 이 클라이언트는 companion service의 dataset lifecycle에 의존합니다.

Problem 02

Stable layout, unstable plane IDs

AR plane은 방이 그대로여도 사라지거나 새 ID로 돌아올 수 있습니다. exact ID를 먼저 찾고 법선·거리· 겹침·크기 점수를 제한된 유예 시간 안에서 비교하며, 모호하면 선택을 보류합니다. 확정 뒤에는 방 프레임을 고정하지만, 휴리스틱이므로 실패 가능성은 남습니다.

Problem 03

Spatial drama without rewriting truth

방에 맞춰 차량을 옮기면서 source trajectory까지 덮어쓰면 리플레이와 분석이 섞입니다. authoritative logical root는 유지하고 EventReplayStage가 방 배치를, VisualMotionRoot가 차량별 presentation effect와 scale을 맡도록 분리했습니다. 종료 시 stage·vehicle transform과 playback state를 복구하며, 공간 연출은 ‘물리적 원본’이 아닌 재구성으로 명시합니다.

07 Spatial decisions

Entry. Hero. Exit.

01 / ENTRY

First wall, inward

첫 번째 벽의 안쪽 방향으로 프레임을 만들고, 방 안에서 연출이 시작되는 방향 맥락을 제공합니다.

02 / HERO

Viewer focus, spatial pose

HMD 시선 또는 Entry–Exit 사이의 자동 지점으로 잡으며, 현재 기본 디오라마가 실제로 맞춰지는 중심입니다.

03 / EXIT

Different wall, outward

Entry와 다른 벽의 바깥 방향을 사용합니다. 현재는 배치 맥락이며 차량의 벽 관통을 보장하는 path constraint는 아닙니다.

09 Technology

Built for a Quest-class XR target.

Android ARM64 / IL2CPP, Mobile URP, OpenXR와 controller-based XRI 상호작용으로 구성했습니다.

Quest 3가 포함된 Meta Quest 대상, passthrough camera, planes, anchors, raycasts, mesh, boundary와 composition-layer feature가 설정되어 있습니다. 다만 이 정적 감사에서는 OpenXR 초기화와 실기기 동작을 실행하지 않았으므로 “Quest 3에서 검증 완료”라고 표현하지 않습니다.

Hand Tracking과 environment occlusion은 현재 플랫폼 설정에서 꺼져 있으며 기술 스택 주장에 포함하지 않았습니다.

11 Evidence & next work

What the repository proves — and does not.

이 페이지의 “Verified”는 코드와 기본 씬 연결을 확인했다는 뜻입니다. 기기 실행이나 성능 보증은 아닙니다.

감사 과정에서 호출점, 직렬화된 컴포넌트, 활성 플랫폼 설정을 우선했습니다. 대체 씬과 미호출 코드는 별도 상태로 내렸고, 테스트·Quest·백엔드는 실행하지 않았습니다.

검증된 중심 경로

REST dataset → manifest/chunks → source/processed samples → shared timeline → multi-driver replay → event-local two-car stage → Hero-centered RoomDiorama. 벽 필터링·재획득·Entry/Exit/Hero·frame freeze가 이 room presentation에 배치 맥락을 제공합니다.

실험 또는 curated 경로

공급된 이벤트 구간 기반 추월/피트 재구성, 현재 작업 트리의 단일 Suzuka collision forensics, 대체 씬의 room-shell transition, life-size/trackside modes, car LOD budget입니다.

공개 주장에 넣지 않은 것

Unity의 OpenF1 직접 연동, live data, 자동 전체 이벤트 검출, connected dual-wall portal, Entry/Exit 차량 관통 보장, full room mesh, hand tracking, environment occlusion, Quest 검증·FPS·latency·accuracy입니다.

Highest-impact next moves.

Priority 01

One path, one source of truth

setup preview와 실제 vehicle mapper가 같은 검증된 Entry/Hero/Exit path를 소비하도록 통합하거나, UX를 현재 Hero 중심 디오라마에 맞춰 단순화합니다.

Priority 02

One releaseable Quest path

누락된 build scene과 localhost 설정을 정리하고, Editor tests·permission·input·passthrough·comfort·profiler를 하나의 Quest 3 release checklist로 검증합니다.

Priority 03

Provenance and rights

backend/OpenF1 변환 출처, curated event 경계, 기여 범위, F1·팀·음원·항공 이미지의 공개 권리를 문서화하고 unwired 실험 코드는 feature gate 또는 제거합니다.
